# 临床医学 AI 学习助手 —— 核心方案（定稿版）

> 决策日期：2026-10-20　｜　申报截止：2026-10-31　｜　开发窗口：11/4–11/25
> 本文只锁定"核心三件事"，新增的督促/病例/题库暂不进入本期范围。

## 一、一句话定位

**一个"答案必须能被翻到"的医学学习助手**：学生问一个问题，系统给出——书上的答案（精确到页码）、前沿文献（带证据等级）、下一步建议（基于他的历史记录）。

不做的：不做通用医学百科、不做诊疗建议、不做题库平台、不做导师库。

## 二、为什么是这三件事

| 能力 | 解决的痛点 | 为什么它是核心 |
|---|---|---|
| 溯源问答 | 答案不知道出处，不敢信 | 医学学习的底线是"可核对"，也是本项目唯一的技术壁垒 |
| 文献支撑 | 教材滞后，学生不会写检索式 | 把"机制未明"的疑问接到前沿，PubMed 免费但没人会用 |
| 个性化建议 | 不知道自己哪里不会 | 让系统从"工具"变成"学习伙伴"，也是 A2 验收要点里的"评" |

三件事共用一条数据链：**提问 → 检索 → 回答 → 记录 → 建议**。这是"智能体"和"聊天机器人"的区别。

## 四、技术架构（定稿）

```
┌──────────────────────────────────────────────────┐
│ 前端  Gradio（三个 Tab：学习 / 文献 / 我的）        │
├──────────────────────────────────────────────────┤
│ 编排  Python 函数式流水线（不用 LangChain）         │
│   ① 查询理解：同义词扩展 + 意图分类                │
│   ② 教材检索：BM25 + 向量 → RRF 融合 → top-5 段块   │
│   ③ 生成：强约束 prompt（只用给定片段 + 强制页码）  │
│   ④ 引用校验：回查页码与原文 → 通过/降级/拒答       │
│   ⑤ 文献：检索式生成 → esearch → efetch → 摘要点评  │
│   ⑥ 建议：读 knowledge_state → 规则生成 → LLM 润色  │
├──────────────────────────────────────────────────┤
│ 数据  段落库 JSONL ｜ 向量 embeddings.npy（离线预算）│
│       SQLite：questions / knowledge_state / feedback│
├──────────────────────────────────────────────────┤
│ 外部  DeepSeek-chat（对话）｜百炼 text-embedding-v3  │
│       PubMed E-utilities（免费，申请 key）          │
└──────────────────────────────────────────────────┘
```

### 关键选型与理由

| 决策 | 选择 | 理由 |
|---|---|---|
| 前端 | Gradio | 中文稳、20 行起页面、可 `share=True` 生成临时链接 |
| 向量库 | **不用**（numpy 暴力检索） | 5,667 块 × 1024 维 ≈ 23MB，毫秒级；少一个依赖少一个坑 |
| 检索 | BM25 + 向量 + RRF | BM25 抓术语精确匹配，向量抓语义，RRF 无需调参 |
| 向量化 | 百炼 text-embedding-v3，**离线预算存 .npy** | 演示当天接口挂了也能检索，容灾关键 |
| 大模型 | DeepSeek-chat，备 qwen-plus | 中文强、便宜、国内直连 |
| 编排框架 | 不用 LangChain | 小项目里它的抽象是负担，直写函数更好解释 |
| 存储 | SQLite | 单机、零配置、够用 |
| 部署 | 本地 localhost + 录屏备份 | 不上云，避免现场网络风险 |

## 五、检索与回答链路（核心 40 行逻辑）

```
query
 └─ 同义词扩展（限速酶→关键酶；三羧酸循环→TCA/柠檬酸循环）
     └─ 并行：[BM25 top-20] + [向量 top-20]
         └─ RRF 融合 → top-5 段块（每块 ≤320 字，带 {书名, 印刷页码}）
             └─ prompt 强约束生成
                 └─ 引用校验
                     ├─ 页码不在检索集合内 → 删除该引用
                     ├─ 该页原文不含结论关键词 → 降级表述
                     └─ 全部不通过 → 拒答："教材中未见明确依据"
```

**页码来源纪律**：页码只来自元数据，永远不由模型生成。三本书的印刷页码偏移需逐本标定（实测：解剖 +19、生化 +29、生理 +23）。

## 六、个性化建议怎么做到"不是玄学"

建议必须由数据算出，LLM 只负责写成人话。规则示例：

| 触发条件 | 输出建议 |
|---|---|
| 同一知识点 7 天内被问 ≥3 次 | "你在这块反复提问，建议系统重读 P{page}–P{page+2}" |
| 自测某知识点正确率 <60% | "该知识点正确率 {x}%，建议先看 P{page} 再做 3 题" |
| 知识点掌握度 >80% 且未复习 >14 天 | "该知识点可能开始遗忘，安排一次 5 分钟回顾" |
| 连续 3 次问同一系统（如呼吸） | "你在呼吸系统投入较多，可尝试文献卡里的综述" |

掌握度更新（20 行代码，可解释）：

```
mastery ← mastery + α × (本次是否正确 − mastery)      # α = 0.3
mastery ← mastery × exp(−Δt / 14)                     # 遗忘衰减，半衰期约 10 天
```

不使用 BKT/DKT：数据量不足、不可解释，答辩时说不清反成减分项。

## 七、验证方案（对应评审六维）

| 指标 | 方法 | 目标 | 当前状态 |
|---|---|---|---|
| 页码命中率 | 30 个真实课程问题，人工核对 | ≥90% | 打样 8 题命中 7（87.5%） |
| 引用可核验率 | 系统内后处理，机制保证 | 100% | 已实现 |
| 拒答准确率 | 20 个教材中不存在的问题 | ≥90% 正确拒答 | 待测 |
| 文献相关性 | 20 个疑问，医学背景同学盲评 | ≥80% 相关 | 待测 |
| 建议可追溯率 | 每条建议是否附数据依据 | 100% | 设计保证 |
| 真实试用 | 10-15 名同学，1 周 | 定性反馈 + 主观评分 | 待开展 |

**话术提醒**：n=15 不做统计推断，只说"定性反馈 + 主观评分"，不要说"显著提升"。

## 八、4 周开发计划

| 周 | 交付 | 验收 |
|---|---|---|
| W1（11/4–11/10） | 段落库 + 混合检索 + 引用校验 + Gradio 单页问答 | 现场问 10 题，页码可核 |
| W2（11/11–11/17） | PubMed 链路 + 三卡输出 + 查询缓存 | 一个疑问 → 3 篇文献 + 中文要点 |
| W3（11/18–11/24） | 个性化建议 + SQLite 记录 + 自测入口 | 连问 5 次后，建议随记录变化 |
| W4（11/25–11/30） | 整合、试用、录屏、答辩材料 | 全流程彩排 3 次 |

## 九、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| embedding 接口调不通 | 高 | 本周先验证；备选智谱；实在不行退回纯 BM25（可用，只是语义召回弱） |
| PubMed 现场连不上 | 中 | SQLite 缓存 + 预置 20 个问题的结果 + 录屏 |
| 页码偏移标定错误 | 中 | 每本书抽 5 页人工核对，写入配置 |
| 教材版权表述 | 中 | 只返回 ≤120 字摘录 + 页码，不输出整页；申报表写明"个人学习用途、不对外分发" |
| 4 周做不完 | 中 | 每周日晚验收，未达标当周砍功能（先砍文献卡，保问答） |

## 十、与赛题的对应关系

- 参赛方向：**校园真实需求挑战**
- 项目来源：**赛事发布任务（附件1 A2）**，并注明"本研究将其收窄为临床医学单科场景"
- 对 A2 验收要点的回应：
  - "完整问答" → 溯源问答
  - "学情诊断" → 基于提问记录与自测的薄弱点诊断
  - "个性化建议" → 建议卡
  - "演示学习闭环" → 提问 → 记录 → 建议 → 回访的完整链路
