# 协作说明 · 书页

> 一页看完：怎么拉代码、怎么开分支、怎么提 PR、哪些文件不能乱动。

---

## 1. 仓库里有什么、没有什么

**有**：全部源码、启动脚本、文档、界面截图。

**没有**（`.gitignore` 已排除，也不允许强推）：

| 文件 | 原因 |
|---|---|
| 三本教材 PDF | 版权，且单文件超过 GitHub 100 MB 上限 |
| `book_*.jsonl`、`chunks.jsonl` | 教材正文与索引，等于公开教材 |
| `libs/` | 旧版 gradio 依赖，269 MB，现已不用 |
| `shuye.db` | 本机提问记录 |
| `python.exe` | 本机解释器副本，换机器无效 |

**所以每位队员本地都要自己准备教材和索引**，见第 3 节。

---

## 2. 环境准备（比想象的简单）

- 只需要 **Python 3.10+**，**不需要 pip install 任何包**（核心链路只用标准库）
- 前端是原生 HTML/CSS/JS，不需要 Node、不需要构建

```powershell
python server.py 7860     # 启动，浏览器打开 http://127.0.0.1:7860
python cli.py "三羧酸循环的关键限速酶"   # 命令行问答
python benchmark.py       # 跑一遍基准，10 题命中 + 4 题拒答
```

Windows 用户也可以直接双击 `启动书页.bat`。

---

## 3. 首次运行：三步把教材装进本地

仓库里没有教材，所以要自己补：

1. 把三本 PDF 放到项目根目录，文件名照抄 `config.py` 里的配置：
   - `07. 局部解剖学（第10版）.pdf`
   - `09. 生物化学与分子生物学（第10版）n.pdf`
   - `10. 生理学（第10版）n.pdf`
2. 抽取逐页文本（每本跑一次，约 30 秒）：
   ```powershell
   python tools/pdf_extract.py "07. 局部解剖学（第10版）.pdf" 100000 book_jiepou.jsonl
   python tools/pdf_extract.py "09. 生物化学与分子生物学（第10版）n.pdf" 100000 book_shenghua.jsonl
   python tools/pdf_extract.py "10. 生理学（第10版）n.pdf" 100000 book_shengli.jsonl
   ```
3. 重建段落索引（会自动生成 `chunks.jsonl`）：
   ```powershell
   python cli.py --rebuild "测试问题"
   ```

> 教材只在本机使用，**不要**为了图方便把 PDF 或 `chunks.jsonl` 提交上去。

## 4. 分支怎么开

`main` 是稳定分支，**不直接改**。每个人在自己的分支上干活。

| 分支名 | 谁用 | 说明 |
|---|---|---|
| `main` | 只接受 PR | 任何改动都要经过一次合并 |
| `feat/<名字>/<做什么>` | 写功能的 | 例：`feat/wang/quiz-page` |
| `fix/<名字>/<修什么>` | 修 bug 的 | 例：`fix/li/page-offset` |
| `docs/<名字>` | 只改文档的 | 例：`docs/zhao/readme` |

GitHub Desktop 操作：`Current Branch → New Branch`，从 `main` 拉出来。

**一条分支只做一件事。** 分支活太久会和 main 冲突，建议 2-3 天合并一次。

---

## 5. 提交信息怎么写

格式：`类型: 一句话说清改了什么`

| 类型 | 用在 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修 bug |
| `docs` | 只改文档 |
| `refactor` | 重构，不改行为 |
| `style` | 格式、空格，不改逻辑 |
| `test` | 测试相关 |
| `chore` | 配置、脚本 |

例子：

```
feat: 新增学习评估页，支持 20 道题与部分正确评分
fix: 修正生理学页码偏移，从 +23 改为 +22
docs: 补充教材重建步骤
```

**不写**“更新”“修改”“提交一下”这类看不出内容的。

---

## 6. PR 怎么提

GitHub Desktop 的路径：

1. 分支上改完 → 写提交信息 → `Commit to <分支>`
2. 右上角 `Publish branch`（第一次）
3. `Create Pull Request` → 浏览器打开 → 填标题和说明 → 提交
4. 至少 **1 个人 review** 后再合并
5. 合并后删除远端分支，本地切回 `main` 拉取最新

PR 说明里建议写三行：

```
改了什么：
为什么改：
怎么验证的：（跑了 benchmark 吗？截图？）
```

## 7. 改这些文件之前，先在群里说一声

不是不让你改，是**改了会影响别人**，需要协调。

| 文件 | 影响 | 规矩 |
|---|---|---|
| `chunks.jsonl` | 全体成员的检索结果与页码 | **只有索引负责人能重建**，见第 8 节 |
| `shuye/config.py` | 书籍清单、页码偏移、同义词、拒答阈值 | 改页码偏移必须说明依据（抽了哪几页核对） |
| `shuye/retrieval.py` | 检索算法与覆盖率阈值 | 改完必须重跑 `benchmark.py` 并贴结果 |
| `shuye/citation.py` | 引用校验逻辑 | 这是核心防线，改动需第二人 review |
| `web/styles.css` | 全局样式 | 大范围改版先画个草图，避免两人同时改 |
| `web/index.html` | 页面结构 | 新增视图要同步在 `app.js` 的 `VIEWS` 里注册 |

**改了检索、校验、配置三处任何一处，PR 里必须贴 `python benchmark.py` 的输出。**

当前基线（不要低于这个）：

```
页级命中  10/10
域外拒答   4/4
```

## 8. 索引只由一个人重建（重要）

`chunks.jsonl` 是**唯一副本**，它决定了所有人看到的页码。两个人各自重建一次，很可能因为 PDF 版本、切块参数、页码偏移不同，导致同一份代码在 A 电脑上引用 P114、在 B 电脑上引用 P119。

规则：

1. **指定一位“索引负责人”**（建议由负责数据的人担任），全队只由他跑 `--rebuild`
2. 重建后把 `chunks.jsonl` 通过**私有网盘**发给大家，或直接约定大家用同一份 PDF 自己跑（二选一，全队统一）
3. 索引有任何变化，负责人在群里通知一句：「索引已重建，请重新拉取」
4. 其他人**只读**，不要为了调试方便自己重建；真要试，先复制一份到别的目录

判断索引是否一致的办法：跑 `python benchmark.py`，页级命中必须是 10/10，且页码与 README 里的一致。

## 9. 代码约定

- 不加新的第三方依赖：核心链路只用标准库（这是这个项目能“解压即跑”的原因）
- Python 遵循 PEP 8，注释用中文
- 前端不引入框架和构建工具
- 每个新功能配一个能在 `benchmark.py` 里复现的用例
- 提交前先本地跑一遍 `python server.py` 看看页面有没有崩

---

## 10. 出问题了怎么办

| 现象 | 处理 |
|---|---|
| 拉下来跑不起来 | 先确认 Python ≥ 3.10，再确认本地有 `chunks.jsonl` |
| 页面 404 | 服务没起来，或端口被占；换端口 `python server.py 7861` |
| 引用页码整体偏了 | 页码偏移错了，检查 `config.BOOKS` 里的 `offset` |
| 改完 benchmark 掉分 | 先回滚，再逐个提交定位，别硬推 |
| 不小心提交了教材 | **立刻告诉负责人**，需要重写历史，越晚越麻烦 |
