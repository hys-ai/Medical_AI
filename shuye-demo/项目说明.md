| 方式 | 操作 | 说明 |

**费用**：不配置 API key 时全程 0 元；配置后每次提问约 0.005 元。

## 二、这个项目想解决什么

医学生查一个知识点，要翻教材、指南、课件好几处；找到了也说不清出自哪一页，不敢直接采信。教材又滞后于前沿，遇到"机制尚未明确"的疑问只能搁置。

而现有的 AI 医学问答有一个共同毛病：**说得头头是道，但你没法核对。**

所以本项目只做一件事：

> **让每个答案都能被翻到。**

一次提问，三张卡：

| 卡 | 回答什么 | 怎么保证可信 |
|---|---|---|
| **答案卡** | 书上怎么说 | 结论必须附「书名 + 印刷页码」，页码来自索引元数据，生成后逐条回查原文 |
| **文献卡** | 前沿怎么说 | PubMed 公开接口，按证据等级标注（综述 / 随机对照 / 队列 / 病例报告） |
| **建议卡** | 我该怎么办 | 读实际提问记录，每条建议都带数据依据，不是模型泛泛而谈 |

查不到就拒答——这是设计上的硬约束，不是兜底。

## 三、技术框架

### 3.1 整体结构

```
浏览器（web/index.html + styles.css + app.js）
        │  HTTP JSON
        ▼
server.py  ←── 只用 Python 标准库 http.server，无框架依赖
        │
        ▼
shuye/  核心包
├── pipeline.py   三卡流水线（编排）
├── retrieval.py  BM25 + 覆盖率重排 + 拒答判定（+ 可选向量检索）
├── citation.py   引用校验（页码复现 + 关键词命中）
├── llm.py        强约束提示词生成 / 离线抽取兜底
├── pubmed.py     检索式生成 → esearch → efetch → 证据分级（SQLite 缓存）
├── store.py      提问记录 + 建议规则
├── index.py      逐页文本 → 段落块（带页码）
└── config.py     书籍清单、页码偏移、同义词表、中英术语表、阈值
```

### 3.2 一次提问的完整链路

```
学生提问
  │
  ├─[1] 同义词扩展      限速酶 → 关键酶 / 限速步骤
  │
  ├─[2] 混合检索        BM25（术语精确）+ 向量（语义）
  │                      → RRF 融合 → 覆盖率重排 → top-5 段落
  │
  ├─[3] 覆盖率闸门      IDF 加权覆盖率 < 0.30 → 直接拒答（不调模型）
  │
  ├─[4] 强约束生成      只允许使用给定片段，每个结论必须带《书名》P页码
  │
  ├─[5] 引用校验        逐条回查：页码在不在本次检索集合里？该页原文有没有这句话？
  │                      → 不通过：删引用 / 降级表述 / 整体拒答
  │
  ├─[6] 文献检索        口语问题 → 英文检索式 → PubMed → 摘要 + 证据等级
  │
  ├─[7] 建议生成        读提问记录，规则算出薄弱点 → LLM 润色
  │
  └─[8] 输出            三张卡 + 引用校验明细 + 覆盖率 + 耗时
```

### 3.3 技术选型与理由

| 位置 | 选择 | 为什么 |
|---|---|---|
| 前端 | 原生 HTML/CSS/JS | 完全可控，样式与「拾词」统一；不引入框架的构建链 |
| 服务 | `http.server` | 零依赖、启动快、代码看得懂，答辩时能一行行讲 |
| 检索 | BM25 + RRF + 覆盖率重排 | 医学术语需要精确匹配，BM25 比纯向量稳；RRF 不需要调权重 |
| 向量库 | **不用**（可选 numpy 暴力检索） | 5,667 块 × 1024 维 ≈ 23MB，毫秒级；少一个依赖少一个坑 |
| 向量化 | 百炼 text-embedding-v3，**离线预算存 .npy** | 演示当天接口挂了照样能检索 |
| 大模型 | DeepSeek（OpenAI 兼容协议） | 中文强、便宜、国内直连；接口协议通用，可随时换通义/智谱 |
| 文献 | NCBI E-utilities | 免费公开接口，无版权风险 |
| 存储 | SQLite | 单机零配置，够用 |
| PDF 解析 | **自写纯标准库解析器** | 环境无外网时 PyMuPDF 装不上，标准库反而更稳 |

### 3.4 三本书的实测数据

| 教材 | PDF 页数 | 可提取页 | 平均字数/页 | 印刷页码偏移 |
|---|---|---|---|---|
| 局部解剖学（第 10 版） | 305 | 305 | 1099 | PDF 页 = 印刷页 **+19** |
| 生物化学与分子生物学（第 10 版） | 577 | 577 | 1382 | **+29** |
| 生理学（第 10 版） | 450 | 447 | 1465 | **+23** |

三本都有完整文字层，无需 OCR。**偏移必须逐本标定**，否则引用会整体偏十几二十页。

## 四、关键技术决策背后的思考

### 4.1 为什么坚持"页码只来自元数据"

模型编造页码是这类系统最致命的问题。所以定了纪律：

> 页码永远不由模型生成；生成完必须回查，对不上就删引用。

这段代码不到 60 行，但它让"页码可验证"从口号变成机制。答辩时现场问一个教材里没有的问题，系统直接拒答——这比讲十分钟架构有用。

### 4.2 为什么拒答判定不交给模型

拒答用的是 **IDF 加权查询覆盖率**：查询词在检索结果里出现了多少权重。

- 交给模型 → 每次结果不一致，演示会翻车
- 用检索统计 → 确定性，离线也能判，可复现

阈值 0.30 是经验值。第一版用普通覆盖率，问"量子纠缠的基本原理"时因为命中"基本""原理"两个高频词而误判，改成 IDF 加权后才拦得住。

### 4.3 为什么必须有离线兜底

没配 API key 时，系统从检索片段里挑与问题最贴近的句子（按命中片段长度加权），仍然带页码、仍然过校验。

理由是：**答辩现场 WiFi 断了，系统照样能出带页码的答案。** 这一点比省几块钱重要得多。

### 4.4 为什么不用现成的 RAG 框架

LangChain / Dify 这类框架在项目里是负担：抽象层盖住了真正要解释的东西。而评审六维里的"智能体方案设计"，考的恰恰是你能不能讲清楚每一步为什么这么做。

40 行直白函数 > 一个黑盒框架。

### 4.5 为什么做"三卡"而不是"五个 Tab"

早期设计过五个功能模块（学习 / 大纲 / 漫游 / 导师 / 模拟病人）。后来砍到三个，因为：

- 评审看的是"做成了什么"，不是"计划了什么"
- 三个功能能串成一条完整的数据链（提问 → 检索 → 回答 → 记录 → 建议）
- 一屏能讲完的故事，比五个模块的记忆点强十倍

被砍掉的：导师匹配、模拟病人、题库对接（都写进了后续规划）。

## 五、遇到的问题与解决

| 问题 | 现象 | 解决 |
|---|---|---|
| 教材 PDF 无 PyMuPDF | 环境无外网，pip 装不上 | 用标准库写了 ObjStm 解析 + ToUnicode CMap 解码 + Form XObject 递归 |
| 印刷页码不一致 | 三本书偏移不同（+19/+29/+23） | 逐本标定写进配置；前置页不参与引用 |
| 术语同义漏检 | 学生问"限速酶"，教材写"关键酶" | 建同义词表，查询时扩展 |
| 长尾词被淹没 | "胃的动脉供应"检索到颅底 | IDF 加权覆盖率 + 覆盖率重排，命中率 9/10 → 10/10 |
| 引用紧跟短句误判 | "（依据…"被当作结论句 | 取前文 80 字窗口比对 |
| 离线检索式查不到 | 中文直接塞进 PubMed | 建 45 条中英术语表（缺氧→hypoxia） |
| 证据分级错位 | "systematic review" 被识别成 "review" | 按特异性从高到低匹配 |
| gradio 装不上 | 沙箱权限 + brotli DLL 拒绝访问 | 最终弃用 gradio，改自写前端 |
| 启动脚本中文乱码 | PowerShell 读 UTF-8 无 BOM 文件出错 | 启动脚本改为纯 ASCII + CRLF，中文路径用 code point 拼接 |

## 七、已知短板（诚实清单）

按严重程度排：

1. **建议卡基于提问次数，不是掌握程度** —— 申报表写的是"学情诊断"，目前只有雏形。补法是加 20 道自测题绑定知识点，用 EMA 更新掌握度。
2. **没有多轮对话** —— 每次提问独立，追问"那它和糖酵解怎么衔接"系统不知道上文。
3. **三张卡并列而非互相印证** —— 教材结论与文献结论的"一致 / 补充 / 争议"关系没有显式标出。
4. **测试集是自出自考** —— 10 题，团队成员出题自己判，缺第三方标注。
5. **零真实用户** —— 申报表写"10-15 人试用"，目前还是空的。
6. **没有对照组** —— 缺"裸模型 vs 本系统"的页码编造率对比，而这正是创新点。

## 九、路线回顾（为什么最后是 A2）

| 阶段 | 曾考虑的方案 | 放弃原因 |
|---|---|---|
| 1 | C5 医学学科画像评估 | 依赖校内学科评估数据，拿不到；且需要 4-6 人 |
| 2 | MedScope 公开文献画像 | 可行但离"学习"远，用户是学科办，学生用不上 |
| 3 | B1 学业预警与学情画像 | 需模拟学籍数据 + ML 建模，4 周难以做出可信闭环 |
| 4 | A2 学研一体化（教材 + 大纲 + PubMed + 导师 + 模拟病人） | 范围过大，导师爬取和模拟病人都是无底洞 |
| **5** | **A2 收窄版：页级问答 + 文献 + 建议** | **采用**：数据全公开、demo 直观、学科壁垒真实 |

收敛的判断标准很简单：**8 周内，能不能交付一个"有真实用户、效果可验证、不碰校内数据"的东西。**

## 十、合规说明

- 不接入任何校内业务系统，不采集个人信息
- 教材为团队成员自购正版教材的本地电子副本，仅本地检索，系统只输出不超过 120 字的摘录，不输出整页、不对外分发
- 文献来自 PubMed 公开接口，证据等级由 PubMed 元数据判定
- 输出不构成诊疗建议
